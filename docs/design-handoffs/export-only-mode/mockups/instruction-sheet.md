# Mockups — `What to do next.html`

The layout of the instruction sheet. Every string is verbatim in
[`../copy.md`](../copy.md) §6; this file is the shape, the visual treatment and
the rules a renderer must follow.

The sheet is the actual feature (`../overview.md` §6). A folder of correctly
named files is not the deliverable — a user who ends up with a working card is.

## 2. The visual treatment

**It must look like Yoto Maker, and it is not a copy of `styles.css`.**

Inline `<style>`, borrowing the app's palette so the page reads as part of the
same product rather than as a generated artifact:

| Element | Treatment |
| --- | --- |
| Page background | `--bg` `#f6f4fb` |
| Each numbered step | A white `--card` block, `--radius` 16px, `--shadow` — the visual echo of `.step` |
| Body text | `--ink` `#241d38`, the app's `"Segoe UI", system-ui, …` stack, 17px |
| Secondary text | `--muted` `#6b6480` |
| Links | `--accent-dark` `#5f43b0`, underlined |
| The file list | `Consolas, "Cascadia Mono", …` at 14px — the `.mono-value` stack |
| Max width | ~720px, centered, matching `<main>` |

**No numbered badges.** The app's `.step h2 .num` circles belong to the four-step
wizard and mean *"one of the four things"*. Reusing them on a different document
with six steps would say something false about the app's own structure. Plain
`1.` `2.` `3.` here.

**The file list is monospace for the same reason `.mono-value` exists**
(configuration-surface `tokens.md` §3a): she is comparing a string on this page
against a string in a file dialog, character by character, and Segoe UI collapses
`O`/`0` and `l`/`I`/`1`. `01 - Chapter One.mp3` against `Ol - Chapter One.mp3`
must not look the same.

**It prints.** No fixed positioning, no dark backgrounds that waste ink, and page
breaks avoided inside a step block. Printing is not the primary medium — a PDF
was rejected for that reason (`../overview.md` §6.1) — but Ctrl+P must give her
something she can put beside the keyboard.

## 3. The missing-track notice — partial runs only

Rendered **above the card name**, at the very top, before anything else.

```
  ╔══════════════════════════════════════════════════════════════════╗
  ║   What to do next                                                ║
  ║   ─────────────────────────────────────────────────────────────  ║
  ║   ┌────────────────────────────────────────────────────────────┐ ║
  ║   │ ⚠️  One of your tracks isn’t here.                          │ ║
  ║   │                                                            │ ║
  ║   │ Yoto Maker couldn’t save “Chapter Four”, so it isn’t in    │ ║
  ║   │ this folder and isn’t in the list below. If you want it on │ ║
  ║   │ the card, go back to Yoto Maker and try again.             │ ║
  ║   └────────────────────────────────────────────────────────────┘ ║
  ║                                                                  ║
  ║   ┌──────────┐                                                   ║
  ║   │  (card   │   Bedtime Stories                                 ║
  ║   │ picture) │   4 tracks · 34 minutes      ← the REAL count     ║
  ║   └──────────┘                                                   ║
  ║   …                                                              ║
```

**This notice, and the sheet's whole contents, are generated from what actually
landed on disk — never from the draft.** A sheet built from the draft would list
five files where four exist, and she would upload a card with a hole in it and
have no way to know.

`../copy.md` §5.6's on-screen sentence — *"The page in the folder lists what's
actually there."* — is a promise about this file. **If the sheet stops being
generated from what landed, that string becomes a lie.**

The count in the header drops with it: `4 tracks`, not `5 tracks`.

## 4. It must be self-contained

Verified constraint, not a preference. The app makes **no external requests
anywhere** (`DESIGN.md` §8) and must not gain one for this.

- Inline `<style>`. No stylesheet link, no web font.
- **The card picture is embedded, not linked.** A relative
  `<img src="Card picture.png">` works from the folder and breaks when the same
  file is served over `http://` from the app (`../overview.md` §7.2). One file,
  one rendering, both routes — a page that is subtly different in two places is a
  page that will drift.
- No script.
- Nothing that requires the app to be running. She may open this a week later
  with Yoto Maker uninstalled, or after copying the folder to another computer,
  and it must still work.

## 5. Sections that appear conditionally

| Section | Appears when |
| --- | --- |
| Missing-track notice (§3) | Any track failed to save |
| The card picture, in the header and in step 4 | The card has a picture. Otherwise **both are omitted entirely** — no placeholder, no "you didn't pick one" |
| The split line, inside step 3 | Any track title ends `(part N)` |
| The MP3-copies line, inside step 3 | Any file was converted |
| The over-a-limit line, inside step 3 | Any track exceeds 100 MB, or the card exceeds 500 MB / 5 hours / 100 tracks (`../copy.md` §5.9) |
| *The little pictures* (§1) | The `Track pictures\` subfolder was actually written, with at least one picture in it (`../overview.md` §9.2). Its **wording** is still true whether or not the website supports per-track pictures — but a page naming a folder she does not have sends her looking for nothing, and the runner skips that subfolder whenever no track resolved a picture |
| The size bullet in *If something doesn't work* (§1) | **Always**, even for a small card |

**The over-a-limit line flags; the troubleshooting bullet carries the numbers.**
Yoto's four limits are written down exactly once on this page, in the footer.
A user reading step 3 needs to know a refusal is possible and is not her fault;
she does not need three figures recited mid-procedure. And the bullet is
unconditional because it is the only entry in that list whose answer she cannot
get from the app — **the app never sees the website's refusal.**

**Step 6 is never conditional and must never be dropped for brevity.** It is the
one step no software can do for her (`SETUP-YOTO-CONNECTION.md:100-104`), it is
the same on both delivery paths, and omitting it is the single most likely way
this feature fails a real user: a correct upload, a blank card, and no idea why.
